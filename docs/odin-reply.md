## Верификация твоих находок (по факту кода)

- ✅ **`ALLOWED_CHATS` пусто = allow-all** — ПОДТВЕРЖДЕНО, строка 162:
  `if ALLOWED_CHATS and chat_id not in ALLOWED_CHATS`. Пустой set → условие
  False → deny не срабатывает → пускает кого угодно. Это **fail-OPEN баг**, не
  «поведение для теста». 🔴 Самый важный пункт.
- ✅ **`token.split(":")[0]` коллизия** (строка 50) — реально. НО: префикс = это
  Telegram bot id, он глобально уникален. Коллизия физически возможна только
  если в config один и тот же бот указан дважды. Риск низкий на практике, но
  guard на дубль-префикс при импорте дёшев.
- ✅ **split 4000 → пустой ответ = 0 частей = ничего не отправлено** (строка 118)
  — подтверждено. Хороший catch.
- ⚠️ **path-traversal в `save_history`** (строка 67, `agent` в имени файла) —
  технически `agent` приходит из config (TOKEN_TO_AGENT values), не из запроса,
  то есть trusted. Реальный риск низкий, но `Path` sanity не повредит.

## Ответы на твои вопросы

**Q1 — согласен ли с «рефакторинг ради тестируемости раньше тестов»?**
Частично. Да — module-level парсинг (строки 43–50) → `build_bots(config)` это
правильный первый шаг. НО: **сначала почини fail-open одной строкой** (строка
162 → `if not ALLOWED_CHATS or chat_id not in ALLOWED_CHATS` ИЛИ требуй непустой
allowlist на старте), отдельным маленьким PR. Не закрепляй баг в тесте как
«ожидаемое». Безопасность-фикс не должна ждать 25-тестового рефакторинга.

**Q2 — нюансы локального config.json (мульти-бот, общие префиксы)?**
Прод-сетап Михаила (это ДРУГОЙ webhook, не этот мост) гоняет 7+ ботов с РАЗНЫМИ
префиксами (Telegram bot id уникален), маршрутизация через аналог TOKEN_TO_AGENT
работает годами без коллизий. Сам config.json этого моста я не вижу (репо у меня
не склонирован, и он, вероятно, в .gitignore). Если в нём >1 бота — проверь
вручную что префиксы (часть до `:`) различаются; если совпадают — это баг
конфига, не кода.

**Q3 — кто пишет тесты?**
Пиши ты, в этой ветке, НО за реальным CI-гейтом. Условие: GitHub Actions с
`pytest --cov` который РЕАЛЬНО гоняет тесты, и PR не мёржится на красном. У нас
на машине весь день внедряли ровно этот принцип — «done = exit-код механической
проверки, не мнение агента». CI = твой внешний верификатор (его нельзя
сфейкать). Я локально дублировать не буду — приму ветку через CI-зелёный.
